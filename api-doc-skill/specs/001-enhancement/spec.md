# api-doc-skill 增强优化

## 功能描述

对现有的 `api-doc` Skill 进行全面增强优化，解决现有设计中的不足，增加更多功能，提升工具的实用性和扩展性。

## 用户故事

**用户故事 1：** 作为开发者，我希望能够解析更多框架的代码（Django REST Framework、Flask 等），这样我可以在不同技术栈的项目中使用这个工具。

**用户故事 2：** 作为开发者，我希望能够批量扫描整个项目并一次性生成所有接口文档，这样我不需要逐个接口手动处理。

**用户故事 3：** 作为开发者，我希望能够管理多个 API 版本，这样在多版本并行开发时文档可以清晰分离。

**用户故事 4：** 作为开发者，我希望能够查看接口变更历史和版本对比，这样我可以追踪接口的演化过程。

**用户故事 5：** 作为开发者，我希望能够导出 OpenAPI/Swagger 格式，这样可以与现有的 API 文档工具链集成。

**用户故事 6：** 作为开发者，我希望工具能够给出清晰的错误反馈和输入验证，这样我可以快速定位问题。

**用户故事 7：** 作为开发者，我希望文档中包含接口测试示例和调用建议，这样可以直接参考进行接口测试。

**用户故事 8：** 作为开发者，我希望图片有可靠的存储和验证机制，这样文档中的图片链接不会失效。

## 现有问题

根据用户反馈，现有设计存在以下不足：

1. **代码解析能力有限** - 仅依赖装饰器语法识别，对非标准写法容错性差
2. **不支持批量生成** - 用户需逐个接口提交，效率低
3. **文档更新不完整** - 更新场景只能输出局部而非完整文档
4. **无 API 版本管理** - 多版本并行时文档管理困难
5. **缺乏输入校验** - 无效代码片段不会报错或给出反馈
6. **缺少测试示例** - 生成的文档不含接口测试建议或示例调用
7. **无 OpenAPI 导出** - 与主流文档生态割裂
8. **图片处理不完善** - 仅支持文件名引用，无实际存储或验证机制

## 功能需求

### 1. 扩展代码解析能力

- 新增支持 Django REST Framework（Python）
- 新增支持 Flask（Python）
- 新增支持 GraphQL 端点定义
- 新增支持 gRPC protobuf 定义解析
- 改进现有解析器的容错性，支持非标准写法
- 增加基于抽象语法树（AST）的解析，提高准确性

### 2. 批量生成功能

- 支持扫描整个项目目录自动提取所有接口
- 支持按文件类型过滤
- 支持排除特定目录（如 `node_modules`, `venv`, `tests` 等）
- 批量生成后一次性更新整个文档
- 新增命令参数 `--scan-dir` 触发批量扫描

### 3. API 版本管理

- 支持在文档中按版本分组
- 支持指定版本号（如 `v1`, `v2`）
- 支持多版本并行展示
- 支持版本变更记录
- 版本对比功能：展示不同版本间的接口差异

### 4. OpenAPI/Swagger 导出

- 支持导出 OpenAPI 3.0 规范 JSON/YAML
- 支持导出 Swagger 2.0 格式
- 从 Markdown 文档反向生成 OpenAPI 规范
- 可集成到 Swagger UI/Redoc 等工具

### 5. 增强输入验证与错误处理

- 对选中代码进行有效性预检查
- 无法解析时给出具体错误原因和修复建议
- 区分不同错误类型：无法识别框架、找不到接口定义、参数解析失败等
- 提供友好的错误提示，帮助用户修正问题

### 6. 接口测试示例生成

- 根据接口定义自动生成 curl 调用示例
- 生成 Python requests 调用示例
- 生成 JavaScript fetch 调用示例
- 提供常见测试用例建议（正常参数、异常参数等）

### 7. 图片存储与验证增强

- 保存图片时验证图片完整性
- 支持图片压缩优化
- 支持检查图片文件是否存在
- 文档生成时自动修复失效的图片链接
- 增强云存储支持（七牛云、阿里云 OSS、企业微信）

### 8. 完整文档重生成

- 更新时重新生成完整文档而非局部替换
- 保证文档格式一致性
- 重新排序接口序号（可选）

## 非功能需求

- 保持向后兼容：现有 Markdown 文档格式无需迁移
- 插件化架构：新增解析器不影响现有代码
- 性能：批量扫描千个文件应在几秒内完成
- 可配置：支持通过配置文件自定义排除规则、输出格式等

## 验收标准

### 代码解析扩展

- [ ] Django REST Framework 的 `@api_view` 装饰器能够正确解析
- [ ] Flask 的 `@app.route` 能够正确解析
- [ ] GraphQL 的 schema 定义能够正确解析
- [ ] gRPC protobuf 能够正确解析为 HTTP 接口（如果使用网关）
- [ ] 非标准缩进或写法能够容错解析

### 批量生成

- [ ] `--scan-dir ./src` 能够扫描目录下所有支持的文件
- [ ] 自动提取所有接口并生成完整文档
- [ ] 能够正确排除不需要扫描的目录
- [ ] 批量扫描后输出扫描统计信息

### 版本管理

- [ ] 能够按版本分组展示接口
- [ ] 支持 `--version v1` 参数指定版本
- [ ] 能够生成不同版本间的变更对比
- [ ] 多版本文档结构清晰可读

### OpenAPI 导出

- [ ] `--export-openapi output.json` 能够导出 OpenAPI 3.0 JSON
- [ ] 所有已解析的接口信息正确映射到 OpenAPI 规范
- [ ] 导出文件能够被 Swagger UI 正确加载

### 输入验证

- [ ] 无效代码给出明确错误信息
- [ ] 空代码提示用户先选中代码
- [ ] 无法识别的框架提示用户支持列表
- [ ] 错误信息帮助用户定位问题

### 测试示例

- [ ] 每个接口自动生成 curl 示例
- [ ] 生成 Python requests 示例
- [ ] 生成 JavaScript fetch 示例
- [ ] 提供测试用例建议

### 图片处理

- [ ] 保存图片时验证文件完整性
- [ ] 检查文档中引用的图片是否存在
- [ ] 云上传失败时给出清晰错误提示

## 不在本次范围内

- 实时在线文档托管服务
- 支持 HTML 页面生成（当前仅 Markdown）
- 支持 Confluence 等第三方平台同步
- 接口在线测试功能（仅生成示例代码）
